Runbook de instalación en sede

Cómo se instaló el piloto real — y cómo se repite en el próximo cliente. Instalación on-prem, air-gapped, desde pendrive: 8 imágenes x86_64 + licencia + instalador. Resultado del 30-jul: todo verde.

Para quién: desde la mudanza del 04-ago, las instalaciones son del departamento Install & Factory (Falime) — este runbook es parte de la dote. La fuente canónica paso-a-paso vive en el repo (deploy/release/INSTALL-CAMARA.md, viaja en el pendrive del cliente); esto es la vista de equipo: topología real, cicatrices y soporte. Cero credenciales acá: viven en sede.env (custodia JF, canal seguro).

01 · La sede real

Topología: dos máquinas, dos mundos

🖥️ delorean 192.168.46.168 · x86_64 · frontal

  • Corre NUESTRO stack: proyecto compose camara, bundle en ~/basa-install/bundle-camara-comercio/.
  • Puertos nuestros: 8080 http · 8443 https (CA interna Caddy) · 8082 docs.
  • ⚠️ También corre el Dokploy/Traefik DE ELLOS en :80/:443 (n8n, OpenWebUI, Qdrant) — jamás tocar. Un redirect nuestro hacia ahí ya causó un incidente; el Caddyfile lleva auto_https disable_redirects y no se quita.
  • delorean JAMÁS corre modelos (regla explícita del cliente y de JF).

🧠 t800 192.168.46.149 · Ryzen AI Max · 128 GB · inferencia

  • Solo accesible desde delorean (firewall): salto SSH vía el frontal.
  • Corre SU llama.cpp (:8080 chat 30B · :8081 embeddings — no tocar) y NUESTRO Ollama (:11434 — qwen3:30b-a3b-instruct + qwen3-embedding:0.6b).
  • Sus GGUF en /opt/models no se tocan. Partición de 98 GB que ya se llenó dos veces: df -h / antes de bajar nada grande.
Acceso remoto: SIN RESOLVER (#80, Falime). Fuera de la sede, hoy todo se ejecuta pasándole comandos a Rafa (IT del cliente, resolutivo). Credenciales SSH: custodia JF, se piden por canal seguro.

02 · El install

Los 10 pasos (así se hizo, así se repite)

1

Preflight del host

uname -m = x86_64 (el instalador se niega solo si no — cicatriz del showstopper arm64) · Docker sin sudo · ~10 GB libres en /var/lib/docker · RAM ≥8 GB (el NLP carga un modelo en memoria) · puertos libres o alternativos. El plugin compose lo trae el bundle.

2

Copiar e instalar — dos comandos

Copiar bundle + .lic del pendrive, descomprimir y:

./install.sh ../camara-comercio-300.lic camara

Con :80/:443 ocupados (el caso real): INGRESS_HTTP_PORT=8080 INGRESS_HTTPS_PORT=8443 antepuestos. Falsa alarma conocida: el motor puede reportar unhealthy en el primer arranque (migraciones) — esperar 2-3 min, no reiniciar. Al final: 8 contenedores arriba.

3

Licencia y génesis — antes del primer login

curl -s http://localhost/api/v1/health/license

Esperado "status":"active" — y anotar el genesis_license_id: es la génesis de auditoría de ESTA instalación y se registra del lado Basa (el ancla del true-up futuro).

4

Primer login

Navegador → la URL de la máquina. Usuario admin + contraseña que se fija en ese momento y queda (12+ caracteres, elegida ANTES, no delante del cliente). En la Cámara la admin raíz es compartida JF/Rafa.

5

Modelo local — la pregunta ANTES de tocar nada: ¿qué modelo tienen ELLOS?

El bundle asume un modelo bajo el alias del cliente, pero el modelo REAL lo dicta ollama list en su máquina. Si difiere: alta por UI (Modelos & Ollama → modelo personalizado → proveedor Ollama, api base la IP del servidor de inferencia) y repuntar el default en Ruteo inteligente (2 clics, al instante). Ollama debe escuchar fuera de localhost (OLLAMA_HOST=0.0.0.0). Para el modo «Auto» del chat: ollama pull qwen3-embedding:0.6b (639 MB, una vez) — sin él no rompe, degrada al default y queda registrado.

🔴 La regla de oro del piloto: tras CADA alta de modelo por UI → docker restart camara-litellm-1 → probar. Sin restart, el Playground «no hace nada» (400 silencioso). Esto es exactamente lo que la spec 033 elimina.

6

Usuarios y Connections

Cada alta pide contraseña propia 12+ (entregada por canal seguro). Cada persona que use API/herramientas necesita además su Connection — la clave se muestra UNA sola vez. Recordatorio de seats: 1 seat = 1 Connection activa (300 en la licencia de la Cámara).

7

Confianza del certificado en los puestos — ANTES de repartir la extensión

Si el acceso va por https con la CA interna (LAN sin dominio público): armar el kit con trust-kit/export-ca.sh, pasar la huella SHA-256 por un canal DISTINTO del que lleva la carpeta, y en cada puesto el instalador (install-ca.bat / install-ca-macos.sh) que coteja la huella antes de instalar y termina en VERDE/ROJO con handshake real.

El fallo real del 30-jul (#51): doble-click en el .crt importa en el almacén del USUARIO, dice «correcta» y el navegador sigue avisando. El .bat es el camino. Esta fricción costó tiempo — va SIEMPRE antes de la extensión.

8

Extensión + herramientas de código

Extensión: cargar descomprimida, y en el popup la URL del gateway con el path completo — http(s)://SERVIDOR/api/v1/gw (sin el path: «servicio no disponible») + la clave de esa persona. Exige https fuera de localhost (por eso el paso 7 va antes). Claude Code: ANTHROPIC_BASE_URL al mismo gateway. VS Code/Copilot custom endpoint: la URL con ?k=sk-basa-… y el modelo local.

9

Smoke test (el de la demo)

Playground con PII española real (DNI con letra, teléfono, IBAN) → pestaña Debugger Técnico: el JSON muestra [PERSON_0], [PHONE_NUMBER_0]… — eso es lo que recibió el proveedor. Que la respuesta muestre los datos reales es lo CORRECTO (des-enmascarado automático).

10

Operar: parar / reiniciar

Siempre con los DOS env-files (sin ellos compose falla):

docker compose -p camara -f compose.prod.yml --profile selfhosted \ --env-file profile/instance.env --env-file profile/secrets.env down
Los NUNCA: no correr issue_dev_license.py (invalida la licencia viva) · no «limpiar» secrets.env · no reiniciar el motor por el unhealthy del primer arranque · no tocar el Traefik del cliente en :80/:443 · las llaves dev de Basa no viajan a instalaciones de cliente (la API key cloud es DEL cliente).

04 · Después del install

Soporte y cómo pasar un fix

  • Canal: interno con el cliente (Rafa = IT, resolutivo; Javi = negocio). Triage según la regla de la casa: instalación/update → Factory · software → Guardian (issue con label de depto).
  • Pasar un fix (runbook probado): build SIEMPRE --platform linux/amd64 → docker save | gzip → transferir (LAN: http.server; remoto: VPS basa-dev) → verificar sha256 → docker load → levantar SOLO el servicio tocado con los dos env-files → verificar health + la superficie afectada de punta a punta.
  • Config del motor: editar profile/config.yaml → copiar al volumen (chown 10001:999) → restart litellm — escritura atómica desde el fix #50.
  • Sin pendrive: los ficheros viven además en el Mac de JF y en el VPS de basa-dev; por HTTP el bundle solo viaja cifrado (lleva los secretos de la instalación — passphrase la tiene JF; la .lic va aparte, es texto).
